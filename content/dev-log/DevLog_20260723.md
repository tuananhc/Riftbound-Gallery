## Decisions Made

- **Proxy EloShowdown API through Next.js rewrites instead of fetching directly from the browser**
  Direct browser `fetch()` calls to `https://eloshowdown.com` were blocked by CORS (`strict-origin-when-cross-origin`). The `remotePatterns` whitelist in `next.config.js` only affects `next/image`, not `fetch()`. Solution: added a rewrite rule mapping `/api/elo/:path*` → `https://eloshowdown.com/api/v1/:path*` so all calls go server-side. No CORS restrictions apply server-to-server.

- **No `<style>` tags — hover and focus states via event handlers only**
  The user profile page had a `<style>` block with class definitions for hover, focus, active, and last-child rules. These were removed entirely and replaced with `onMouseEnter`/`onMouseLeave` (direct `e.currentTarget.style` mutation) and `onFocus`/`onBlur`. Active/selected states (tabs, filter pills) are driven by existing React state via conditional inline style expressions. CLAUDE.md was updated to ban `<style>` tags, including for hover and animation rules.

- **Country flags via ISO code lookup in `src/lib/countries.js`**
  Rather than storing flag emojis directly, the helper maps country name → ISO 3166-1 alpha-2 code, then converts each letter to a Unicode regional indicator symbol (`String.fromCodePoint(0x1F1E6 + charCode - 65)`). Unknown countries fall back to 🌐. Extracted to `src/lib/countries.js` for reuse across components.

- **EloShowdown has no public match-detail endpoint — match IDs are internal**
  Investigated whether match IDs in the ELO history payload (e.g. `1859602`) could be resolved to event/store data via EloShowdown's API or the UVS Games organised play site. The EloShowdown API only exposes `GET /search`, `GET /players/{id}`, and `GET /seasons`. UVS Games has no public match lookup. Match IDs are EloShowdown-internal, generated from community-submitted results. Contact `eloquest.ink@gmail.com` for undocumented endpoints.

## Topics Discussed

- **Why `remotePatterns` doesn't fix CORS** — `remotePatterns` gates the `next/image` optimisation pipeline, not general network requests. It has no effect on browser `fetch()` calls.
- **EloShowdown API exploration** — Confirmed working endpoints via direct probing: `/api/v1/search?q=`, `/api/v1/players/{id}`, `/api/v1/seasons`. Probed `/api/v1/matches/{id}`, `/api/v1/players/{id}/history`, `/api/v1/events` — all 404. The API docs page (`/api/v1/docs`) returns only a title with no content.
- **UVS Games organised play** — EloShowdown's footer notes it is not affiliated with UVS Games or Riot Games. UVS Games runs official Riftbound organised play (uvsgames.com/organized-play). Their site is marketing-only with no match/event lookup. The `riftbound_id` field on player objects (e.g. `"165615"`) may correspond to something on the UVS side but no public URL pattern was found.
- **Clustering matches by date as a proxy for event** — Since matches on the same date in the ELO history likely come from the same store event, the `date` field can be used to group matches by event even without a dedicated event endpoint.

## Bug Fixes

- **CORS error on EloShowdown fetch**
  Browser blocked direct `fetch('https://eloshowdown.com/...')` due to `strict-origin-when-cross-origin` policy. Fixed by routing all calls through the Next.js rewrite proxy (`/api/elo/:path*`). Requires `npm run dev` restart to pick up config changes.

- **Wrong fetch URL for ELO history (missing `players/` segment)**
  `fetchEloHistory` was calling `/api/elo/${playerId}/elo-history`, which the rewrite resolved to `https://eloshowdown.com/api/v1/${playerId}/elo-history` (404). Correct URL is `https://eloshowdown.com/api/v1/players/${playerId}/elo-history`. Fixed by updating to `/api/elo/players/${playerId}/elo-history`.
