## Decisions Made

- **Frontend reaches DynamoDB via HTTP API (v2) + Lambda + a Cognito JWT authorizer.**
  Chose HTTP API over REST API because its JWT authorizer exposes claims at
  `event.requestContext.authorizer.jwt.claims.sub` — exactly the path CLAUDE.md
  already assumes. The authorizer validates signature/expiry/issuer/audience
  before the Lambda runs; the Lambda derives identity from `claims.sub` and never
  trusts a body `userId`. Send the **ID token** (its `aud` = the app client id).

- **Match history is stored as separate items, never embedded in the user item.**
  DynamoDB TTL is per-item, so individual matches can only auto-expire as their
  own items; embedding also risks the 400KB limit and forces whole-item rewrites
  to edit one match. Schema: `PK = userId (sub)`, `SK = matchId (ULID, time-
  sortable)`, queried newest-first with `Limit` + pagination.

- **Dropped TTL from MatchHistory and DeckVersions — they persist indefinitely.**
  Users own and edit this data, so auto-expiry actively fights the intent (a
  90-day TTL would silently delete editable history / version audit trails).
  Storage cost is negligible; bound read size with pagination, not deletion.
  Updated the DynamoDB rule in CLAUDE.md accordingly.

- **Aggregate metrics live as rollup counters on the Users profile item.**
  `wins` / `losses` / `draws` / `currentStreak` are maintained on the profile row
  and updated atomically with each match write via `TransactWrite`, so the profile
  read stays O(1) instead of scanning all history. Win rate is derived on read
  (not stored). Streak is order-dependent, so it's recomputed from a bounded
  recent query rather than trusted as a stored counter after edits.

- **Kept a dedicated Users table (single-table vs multi-table left open).**
  Discussed consolidating user-scoped entities into one table keyed by `sub`
  (idiomatic for "always queried with the user"), but kept the separate `Users`
  table for now to match the existing design; the sync Lambda writes to it.

- **The profile-sync Lambda is a Cognito Post-Confirmation trigger, not an API route.**
  Cognito invokes it directly on signup confirmation — no API Gateway, no HTTP
  method. HTTP methods (GET/POST/PUT/DELETE) only apply to the data endpoints
  (`/me`, `/history`), where PUT is the edit-and-sync path.

- **Champion selection is driven by legends from the card store.**
  Legends are Riftbound's champions, so the match-row picker filters the shared
  `useCards()` store the same way `DeckSources` does
  (`card_type_text.includes("Legend") && isBaseCard(id)`) rather than a bespoke
  list.

- **Selected champion art fills each half of a match row via an overlay layout.**
  Left half = your champion, right half = opponent's, each clipped so art never
  overflows the row, with the match info floating in a gradient-darkened centre.

- **Removed the deck and dummy match-history tabs from the profile page.**
  The real match history now comes from the EloShowdown search, so the tab
  scaffolding and dummy `DECKS` / `MATCH_HISTORY` were removed, leaving just the
  Profile Header and the EloShowdown section.

- **No vertical alignment in code, enforced by a new CLAUDE.md rule.**
  Padding assignments/object keys to line up `=`/`:` produces whitespace-only
  diffs and fights the formatter. Added a Formatting rule under Component
  Conventions and de-aligned `src/app/user/page.js`.

## Changes in Code

- **`lambda/syncUserProfile.mjs`** *(new)*
  Cognito Post-Confirmation trigger. On `PostConfirmation_ConfirmSignUp` it writes
  a `Users` row keyed by `sub` (email, displayName, createdAt), strips
  null/empty fields, and uses `attribute_not_exists(userId)` to stay idempotent.
  Returns the event unchanged so Cognito doesn't fail the sign-up.

- **`CLAUDE.md`** *(modified)*
  Changed the DynamoDB rule: MatchHistory/DeckVersions persist indefinitely with
  no `ttl`, bound reads with pagination. Added a Formatting subsection under
  Component Conventions forbidding vertical alignment.

- **`src/app/user/page.js`** *(modified, extensively)*
  - Removed the dummy match-history tab section and, subsequently, the entire
    deck tab + list, including their state (`activeTab`, `historyFilter`,
    `expandedDeck`, `hoveredTab`, `hoveredDeck`) and the `lib/cards/data` import.
  - De-aligned all code in the file.
  - Added a **Load More** button to the ELO match history (`ELO_PAGE_SIZE`,
    `eloVisible`), resetting on new search and on clearing the linked player.
  - Moved the search form to the **top** of the EloShowdown card, above the
    linked-player chip and history.
  - Built the **champion selector**: `matchChampions` state + `setChampion`,
    legends derived from `useCards()`, and a `ChampionHalf` component that fills
    each half of a match row with the selected legend's art (clipped, gradient
    fade toward centre, click-to-pick dropdown). Tuned art framing with
    `objectPosition: "center 10%"`.
