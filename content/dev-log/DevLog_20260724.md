# Friday 24 July 2026 - Dev Log No. 8

Designed and built the full client-side authentication layer for Riftbound on
AWS Cognito — signup, email confirmation, sign-in, logout, and a shared session
hook — and wired auth state through the navbar and profile page. Resolved the
Cognito app-client and user-pool configuration issues (client secret, email
alias) that blocked signup, and settled the architecture question of how the
frontend should talk to DynamoDB for authenticated data.

---

## Decisions Made

- **Auth/data layer goes through Lambda + API Gateway, not Next.js Server Actions on Vercel.**
  Keeps AWS credentials off Vercel (Lambda uses an IAM role), and an API Gateway
  Cognito JWT authorizer validates tokens declaratively before any code runs.
  Consistent with the committed architecture in CLAUDE.md. Verified against past
  logs: the 28 May decision to use a Route Handler was specific to *live crawling*
  (streaming, no storage) — authenticated, storage-backed writes (decks, match
  history) stay on Lambda. Noted this was never a documented head-to-head, so
  choosing the Vercel-native path later would be a new decision, not a reversal.

- **Cognito is the identity store; DynamoDB stores profile, not credentials.**
  Passwords are hashed and held inside the User Pool and never touch our database.
  The `Users` table stores profile fields keyed by the Cognito `sub`. This
  corrects the initial framing of "store user credentials on DynamoDB."

- **Read path mirrors the write path, keyed on `sub` from the verified JWT.**
  Profile = `GetCommand` (single item); decks and match history = `QueryCommand`
  by `userId` (= sub) as partition key, which needs **no GSI** — staying within
  the "no GSIs unless required" rule. MatchHistory queries are naturally bounded
  by the 90-day `ttl`.

- **Authenticated user data is fetched client-side, not in a server component.**
  The JWT lives in `localStorage` (browser), which a server component can't read.
  The "server components fetch data" convention applies to *public* data (cards,
  news); per-user authenticated data is the documented exception.

- **Cognito app client must be SPA type with no client secret.**
  A browser can't safely hold a secret, and `amazon-cognito-identity-js` can't
  compute `SECRET_HASH`. App type is fixed at client creation.

- **User pool uses email as an alias → register with a generated username.**
  Signup registers with `crypto.randomUUID()` and passes email as an attribute;
  login authenticates with the email (the alias resolves it). The pool forbids
  email-format usernames and its alias/username mode can't be changed post-creation.

- **`useAuth` is a plain hook, no Context/provider.**
  Each consumer does its own cheap `localStorage` session read, respecting the
  "no context without clear justification" rule. Logout redirects to `/login`,
  so cross-component reactivity isn't needed.

- **Session persists in `localStorage`** (the SDK default) — survives reloads and
  tabs until the refresh token expires. Standard SPA tradeoff accepted.

- **Matched the app's actual `Segoe UI` font, not CLAUDE.md's Cinzel/Crimson Pro.**
  Every existing page and `BASE_STYLES` in `src/lib/data.js` use Segoe UI; the
  auth pages match that for visual consistency. Flagged as a standing discrepancy
  against CLAUDE.md to reconcile later.

- **Simplified the navbar auth UI.**
  Signed out shows a single gold **LOG IN** button (dropped SIGN UP for a cleaner
  layout; signup is still reachable from the login form). Signed in shows a dummy
  avatar that opens the profile/logout dropdown.

## Changes in Code

- **`src/lib/cognito.js`** *(new)*
  Lazily-constructed `CognitoUserPool` from `NEXT_PUBLIC_COGNITO_POOL_ID` /
  `NEXT_PUBLIC_COGNITO_CLIENT_ID`. Lazy so the app renders even when env vars are
  unset — callers hit a friendly error only on submit.

- **`src/components/auth/SignupForm.js`** *(new)*
  Client component with a three-phase flow: signup → email-code confirm → done.
  Registers with a generated username + email attribute, with resend-code support.
  Later refactored to import the shared form primitives.

- **`src/app/signup/page.js`** *(new)*
  Server component rendering `SignupForm`.

- **`src/components/auth/formPrimitives.js`** *(new)*
  Shared `Field`, `Input`, `SubmitButton`, and `FONT` used by both auth forms —
  extracted to avoid duplication. `SubmitButton` is the gold CTA style.

- **`src/components/auth/SignInForm.js`** *(new)*
  Client component authenticating with email/password via SRP; caches tokens and
  redirects to `/user`. Maps `NotAuthorizedException` /
  `UserNotConfirmedException` to friendly messages.

- **`src/app/login/page.js`** *(new)*
  Server component rendering `SignInForm`.

- **`src/hooks/useAuth.js`** *(new)*
  Reads the Cognito session on mount (auto-refreshing expired tokens) and exposes
  `status` (`loading`/`authed`/`guest`), `user` (`{ email, sub }`), `token` (ID
  JWT), `signOut`, and `refresh`. Includes a documented `eslint-disable` for the
  one-time mount hydration.

- **`src/components/Navbar.js`** *(modified)*
  Integrated `useAuth`. Conditional right-side UI: single gold LOG IN button when
  guest, dummy avatar + dropdown when authed, nothing while loading. Logout wired
  to `signOut()` then redirect to `/login`.

- **`src/app/user/page.js`** *(modified)*
  Added auth gating — redirects guests to `/login` and renders nothing until
  `status === "authed"`. Decks/match-history still dummy pending the backend.

## Bug Fixes

- **`SECRET_HASH was not received`** — the app client had been created *with* a
  client secret, which the browser SDK can't use. Fixed by creating a **SPA-type
  app client with no secret** and swapping the new Client ID into `.env.local`.

- **`Username cannot be of email format`** — the pool is configured with email as
  an **alias**, which forbids email-format usernames. Fixed by registering with a
  generated UUID username and passing email as an attribute; login still uses the
  email alias.

- **`react-hooks/set-state-in-effect`** lint error in `useAuth` — the mount effect
  sets state synchronously. Legitimate one-time hydration from `localStorage`
  (can't use a `useState` initializer without an SSR hydration mismatch);
  resolved with a documented `eslint-disable-next-line`.

- **`react/no-unescaped-entities`** — an apostrophe in `SignupForm`'s resend text;
  escaped to `&apos;`.

- **Refactor breakage** — duplicate `Field` identifier and adjacent-JSX parse
  errors while extracting `formPrimitives`; resolved by removing the local copies
  and closing the new conditional blocks.
