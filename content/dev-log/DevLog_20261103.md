# Tuesday 3 November 2026 - Dev Log No. 16

Added match notes for reviewing games. Every match on the History tab now has
a free-text note for what happened and what went wrong. A new NOTES tab
collects the notes and filters them by your legend and the opponent's, so you
can read back one matchup. Both work on desktop and phones.

---

## Decisions Made

- **Store notes on the existing MatchHistory item, not in a new table.**
  - The item schema already had a `notes` attribute (capped at 2000 characters), and `getMatchHistory` already returned it. Nothing in the UI used it yet.
  - A note belongs to exactly one match, so keeping it on that match's item means no new keys, routes or CI permissions.
- **Notes save themselves instead of waiting for "Save match history."**
  - Legend picks and scores are quick taps, so it's fine for them to wait for Save. A paragraph of notes is too much work to lose if the user forgets to press Save or closes the tab.
  - Signed in, a note saves about 1 second after the last keystroke, or straight away when the box loses focus (desktop) or the sheet closes (phone).
  - The editor shows its state: SAVING…, SAVED, or an error.
- **An autosaved note is sent as its match row without the picks.**
  - The save Lambda clears any pick sent as null. Leaving `myChampion`, `opponentChampion` and `score` out of the payload means an autosave never touches stored picks the user hasn't saved yet.
  - The rest of the row (result, opponent, event, Elo, season) is still sent. That way, a note on a match that was never saved creates a complete item, not one with only a note on it.
- **Notes are kept with the per-match picks in page state** (`{ mine, opponent, score, notes }`).
  - Notes then go through the paths picks already use, with no extra plumbing: the guest draft in sessionStorage, carrying guest work over on login, the bulk Save, and showing picks from an old EloShowdown row on the BoundRift row that replaced it.
- **Guests can write notes, kept in the tab like their picks.**
  - Their notes count as unsaved picks on the phone save bar and trigger the "leave site?" prompt. Logging in and pressing Save stores them.
  - A note that has already autosaved isn't counted as unsaved. Otherwise the save bar would flash on every keystroke.
- **An emptied note is removed from the item, not left behind.**
  - `notes` was added to the Lambda's `CLEARABLE` list, the same way picks are cleared. A note sent as null is REMOVEd, never stored as null.
- **Notes can't be edited until the saved matches have loaded** (when signed in).
  - Otherwise a note could be typed over a stored note the page hasn't shown yet.
- **The NOTES tab is read-only, with two filters: YOU (your legend) and VS (their legend).**
  - Each filter only offers legends that still have notes under the other filter, with counts, so every option shows at least one note. Matches with no legend picked can be filtered as "Not picked".
  - It shows the filtered note count and W/L/D record, so a matchup's notes come with how that matchup has gone.
  - It follows the season selector and covers every linked account, like the Data tab. The active account's notes come from the page, so a new note appears as it's typed. Other accounts' notes come from what's stored.
  - Editing stays on the History tab. Editing inside a filtered list would make a card disappear when its text was cleared.
- **Desktop: a note button as the last column of each History row, opening a box under the row.** Phones: a note icon on the row's first line, a 2-line preview once a note exists, and a bottom sheet for writing (16px text, so iOS doesn't zoom).
  - The extra desktop column moves the centred result slightly off-centre. That was accepted over making every row taller.

## Bug Fixes

- **A note emptied of all its text could never be removed from the database.**
  - Root cause: the save Lambda strips empty strings before writing, and `notes` wasn't in `CLEARABLE`, so an emptied note was silently skipped and the old text stayed.
  - Fix: `notes` is now in `CLEARABLE`, and the page sends an emptied note as `null`, which REMOVEs the attribute.
