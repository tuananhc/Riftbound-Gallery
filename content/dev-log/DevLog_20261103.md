# Tuesday 3 November 2026 - Dev Log No. 16

Added match notes for reviewing games. Every match on the History tab now has
a free-text note for what happened and what went wrong. A new NOTES tab
collects the notes and filters them by your legend and the opponent's, so you
can read back one matchup. Both work on desktop and phones.

---

## Decisions Made

- **Store notes on the existing MatchHistory item, not in a new table.**
  - The item schema already had a `notes` attribute (capped at 2000 characters), and `getMatchHistory` already returned it. Nothing in the UI used it yet.
  - A note belongs to exactly one match, so keeping it on that match's item means no new keys, routes or CI permissions.
- **Notes save themselves instead of waiting for "Save match history."**
  - Legend picks and scores are quick taps, so it's fine for them to wait for Save. A paragraph of notes is too much work to lose if the user forgets to press Save or closes the tab.
  - Signed in, a note saves about 1 second after the last keystroke, or straight away when the box loses focus (desktop) or the sheet closes (phone).
  - The editor shows its state: SAVING…, SAVED, or an error.
- **An autosaved note is sent as its match row without the picks.**
  - The save Lambda clears any pick sent as null. Leaving `myChampion`, `opponentChampion` and `score` out of the payload means an autosave never touches stored picks the user hasn't saved yet.
  - The rest of the row (result, opponent, event, Elo, season) is still sent. That way, a note on a match that was never saved creates a complete item, not one with only a note on it.
- **Notes are kept with the per-match picks in page state** (`{ mine, opponent, score, notes }`).
  - Notes then go through the paths picks already use, with no extra plumbing: the guest draft in sessionStorage, carrying guest work over on login, the bulk Save, and showing picks from an old EloShowdown row on the BoundRift row that replaced it.
- **Guests can write notes, kept in the tab like their picks.**
  - Their notes count as unsaved picks on the phone save bar and trigger the "leave site?" prompt. Logging in and pressing Save stores them.
  - A note that has already autosaved isn't counted as unsaved. Otherwise the save bar would flash on every keystroke.
- **An emptied note is removed from the item, not left behind.**
  - `notes` was added to the Lambda's `CLEARABLE` list, the same way picks are cleared. A note sent as null is REMOVEd, never stored as null.
- **Notes can't be edited until the saved matches have loaded** (when signed in).
  - Otherwise a note could be typed over a stored note the page hasn't shown yet.
- **The NOTES tab is read-only, with two filters: YOU (your legend) and VS (their legend).**
  - Each filter only offers legends that still have notes under the other filter, with counts, so every option shows at least one note. Matches with no legend picked can be filtered as "Not picked".
  - It shows the filtered note count and W/L/D record, so a matchup's notes come with how that matchup has gone.
  - It follows the season selector and covers every linked account, like the Data tab. The active account's notes come from the page, so a new note appears as it's typed. Other accounts' notes come from what's stored.
  - Editing stays on the History tab. Editing inside a filtered list would make a card disappear when its text was cleared.
- **Desktop: a note button as the last column of each History row, opening a box under the row.** Phones: a note icon on the row's first line, a 2-line preview once a note exists, and a bottom sheet for writing (16px text, so iOS doesn't zoom).
  - The extra desktop column moves the centred result slightly off-centre. That was accepted over making every row taller.

## Bug Fixes

- **A note emptied of all its text could never be removed from the database.**
  - Root cause: the save Lambda strips empty strings before writing, and `notes` wasn't in `CLEARABLE`, so an emptied note was silently skipped and the old text stayed.
  - Fix: `notes` is now in `CLEARABLE`, and the page sends an emptied note as `null`, which REMOVEs the attribute.

# Tuesday 3 November 2026 - Dev Log No. 16 (continued)

A second session, running since Dev Log No. 14. It added the Nexus Night tab for
drafting games at local events, and redesigned the profile's user card around
the signed-in account and the last legend played. It also ran several copy and
font fixes, and built Sideboard Notes: a per-matchup binder with game 1
(blind), on-the-play and on-the-draw plans, battlefields and card swaps, now in
its own DynamoDB table.

---

## Decisions Made

- **Nexus Night drafts are stored in the database and auto-fill History.**
  - Drafts are saved to the account rather than the browser, so a game logged
    on a phone at the venue can be reviewed on a laptop later. Guests fall back
    to localStorage.
  - Once the results arrive, each drafted game is paired with its official row
    by opponent name (any case) within a day of the event date. Its legends and
    score then fill only picks that have never been set, so a pick the user made
    or cleared is never overwritten.
  - The filled picks show as unsaved, so the user reviews them and presses Save.
    Nothing is written to their history automatically.

- **The user card shows the real account and no emoji.**
  - The placeholder "ShadowRift", rank, title and emoji were dropped. The card
    shows the Users row's `displayName` (the email before the @), the sign-in
    email and the real sign-up date.
  - The avatar is the icon of the last legend played, falling back to initials.
    A fake rank and title on a real profile was misleading.

- **Sideboard Notes uses layout B, the binder.** Of three proposals (cards with
  filters, binder, matrix), the binder was chosen because you reach any matchup
  in two clicks: your legend, then theirs. The proposals were shown as an
  interactive preview page.

- **One note per matchup, covering three game states.**
  - Game 1 is played blind with the main deck, so it holds a battlefield and a
    plan, with no IN/OUT. The Lambda rejects any swaps sent for it.
  - Games 2–3 keep separate battlefield, IN, OUT and plan for on the play and on
    the draw, because the right swaps often differ.

- **Each legend has three battlefields, set once.** You bring three battlefields
  with a legend, so each game's battlefield is picked from that set. This is one
  click and shows which ones you aren't using. A note still pointing at a
  battlefield since removed from the set is flagged.

- **Notes are laid out as one grid with fixed rows.**
  - On desktop, Battlefield / IN / OUT / Plan run across the Blind / Play / Draw
    columns as one grid, so rows line up however long a card list is. Blind's
    IN/OUT cells say "Main deck" and "—" instead of collapsing.
  - A blue square marks cards that differ between play and draw.
  - On a phone, three summary tiles (battlefield art plus swap count) choose
    which game's rows to show.

- **The card list for the pickers loads on demand.** It comes from a new
  `/api/cards/sideboard` route the first time the tab opens (about 1,100 cards
  plus 72 battlefields), so the profile page's initial load stays light.

- **Sideboard notes moved to their own `SideboardNotes` table.**
  - They were first stored in `MatchHistory` under `~side#` keys. That avoided a
    manual bootstrap deploy, because CI's CloudFormation role may only manage
    the `MatchHistory` and `Users` tables.
  - The user questioned it, and the trade-off didn't hold up: the table name
    became misleading, each Lambda's IAM role could reach the whole table, and
    sideboard notes are never read alongside matches.
  - The new table is owned by the backend stack, keyed `userId` + `noteKey`
    (`<my>|<opp>` for notes, `bf#<my>` for battlefield sets), on-demand,
    Standard class, retained on delete. It needs one manual update of the
    bootstrap stack.
  - Nexus Night drafts and unofficial matches stay in `MatchHistory` for now.

## Bug Fixes

- **Battlefields vanished a moment after being added (signed in).**
  - Root cause: the pushed commit `262503e` deployed the first sideboard Lambda,
    which needs an `oppLegend` on every PUT, so the battlefield-set request got
    a 400. The page's optimistic update was then silently rolled back.
  - Fix: the battlefield-aware Lambda is ready to deploy, and a failed save now
    shows "Couldn't save your battlefields, so the change was undone" instead of
    failing silently.

- **"Couldn't load your sideboard notes" after the tab first shipped locally.**
  - Root cause: `/sideboard` didn't exist on the live API (404) because the
    Lambda hadn't been deployed.
  - Fix: deploy; it was resolved by the `262503e` push.

- **The sideboard binder had no legend chip on a profile with no picks.**
  - Root cause: chips came only from played legends, while the binder fell back
    to the first legend.
  - Fix: the selected legend is always shown as a chip.

- **The battlefield-set PUT rejected a list with a duplicate entry.**
  - Root cause: the length check ran before duplicates were removed.
  - Fix: duplicates are removed first.

- **The "BATTLEFIELD" row label ran into the grid's border.**
  - Root cause: the label column was too narrow.
  - Fix: widened from 84px to 104px.
