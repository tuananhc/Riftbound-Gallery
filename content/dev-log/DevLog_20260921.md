# Monday 21 September 2026 - Dev Log No. 11

Polished the match history UI on the profile page (legend picker, row sizing,
per-tournament grouping, centred layout), then reworked the backend so users
can link one or more EloShowdown/UVS accounts to their profile instead of
searching every visit. Finalised the MatchHistory item schema and re-keyed it
per linked account.

---

## Decisions Made

- **Legend picker sorts by `tags_text`, not `name`.**
  Players identify legends by their champion tag (e.g. "Jinx"), which is also
  what the picker displays; sorting by card name produced an order that didn't
  match what was on screen. `name` is kept as a tie-breaker.

- **Opponent name is centred with a `1fr auto 1fr` grid.**
  The previous flex row centred the whole result/name/ELO group, so the name
  drifted with the width of "LOSS" vs "WIN" or a two- vs three-digit ELO change.
  Equal outer columns pin the name to the exact centre regardless.

- **Per-row date removed; each tournament group is its own bordered block with
  spacing below.** The date already appears in the group header, so repeating
  it per row was noise.

- **MatchHistory item schema fixed to eight user-facing fields:** `matchId`,
  `opponent`, `myChampion` (your legend), `opponentChampion`, `result`,
  `playedAt`, `eventName`, `notes` (+ `updatedAt`). `eloChange`, `eloAfter`,
  and `season` were dropped at the user's request. `eventName` is filled from
  the resolved UVS tournament name.

- **Match writes use `UpdateItem` (SET only sent fields) instead of `PutItem`.**
  A bulk re-save from the page doesn't include notes, so a Put would have wiped
  them. Updating only the provided attributes lets notes survive re-syncs.
  Trade-off: an attribute can't be cleared by sending an empty value (empty
  values are stripped per the no-null rule) — an explicit clear will need a
  REMOVE path later.

- **Linked EloShowdown accounts are stored on the Users item.**
  Avoids forcing users to search for themselves on each visit. The search box
  only appears when no account is linked (or when adding another); otherwise the
  page goes straight to match history.

- **Users can link multiple accounts.** Stored as `eloPlayers` (list of
  `{ id, display_name, primary_community, country }`, max 10) plus
  `activeEloPlayerId`. A list on the profile item was chosen over a separate
  table since it's small, always read with the profile, and needs no GSI.
  Writes are read-modify-write guarded by an `updatedAt` condition so two tabs
  can't silently drop each other's changes (loser gets a 409). Legacy single
  `eloPlayer` items migrate on read.

- **One `PUT /profile` route with an `action` field (`add` / `select` /
  `remove`)** rather than separate REST routes — fewer API Gateway routes to
  wire and one Lambda to deploy.

- **MatchHistory sort key changed to `accountMatchId` = `<eloPlayerId>#<matchId>`.**
  With multiple accounts, two of a user's own accounts playing each other would
  collide on the same `matchId`. The composite key keeps them distinct and lets
  one account's history be queried with `begins_with`. This supersedes the
  29 July plan of a ULID `matchId` sort key. Requires (re)creating the table
  since key names can't be changed in place.

  - Legend picker dropdown widened (280px, max 360px tall, larger rows,
    27×36 thumbnails, 14px text).

    escape the card.
  - Match rows 30px → 44px with larger text; per-row date removed; grid layout
    centres the opponent name; groups are separate bordered blocks with 12px

  - Save payload sends `eloPlayerId` and `eventName`; ELO/season fields removed.

  - Added `getProfile`, `addEloAccount`, `selectEloAccount`, `removeEloAccount`.

  - `GET /profile` returns the Users row with normalised `eloPlayers` /
    `activeEloPlayerId`; `PUT /profile` handles `add` / `select` / `remove`
    with optimistic locking on `updatedAt`.

## Bug Fixes

- **Opponent name not centred in match rows** — root cause: flex row centred the
  result/name/ELO group as a whole, so varying widths shifted the name. Fixed
  with a `1fr auto 1fr` grid.
- **Re-saving match history would wipe notes** — root cause: `PutItem`
  replaces the whole item. Fixed by switching to `UpdateItem` with SET on
  provided fields only.
- **Stale history could overwrite the current account's** — root cause: no
  guard on out-of-order `elo-history` responses when switching. Fixed with a
  `historyRequest` ref that drops responses for a non-current account.
