# Wednesday 20 May 2026 - Dev Log No. 4

Fixed several bugs across the deck builder and server/client boundary, hardened the server layer with `server-only` guards, replaced a broken caching approach with ISR, and built out the new Community Decks page with source widgets and a filter panel. Deck variant handling was also corrected to group by card name rather than card ID.

---

## Decisions Made

- **Group deck variants by card name, not card ID**
  Card IDs encode variant suffixes (`SFD-100a/200`, `SFD-100*/200`) but variant cards share the same name. Using `card.name` as the grouping key in `addToDeck`, `deckCount` lookups, and the validator means all variant copies count toward the same limit without needing an ID-normalisation step. The `baseCardId` regex helper was removed.

- **ISR instead of `unstable_cache` for card fetching**
  `unstable_cache` stores data in Next.js's in-memory data cache, which has a hard 2 MB per-entry limit. The full card dataset exceeds this. Replaced with `export const revalidate = 3600` on `page.js`, which triggers ISR — Next.js caches the fully rendered page output on disk with no size cap. The DynamoDB scan runs once per hour in the background, not per request.

- **`server-only` guard on both `db.js` and `cards.js`**
  Per CLAUDE.md guidelines, any `lib/` file that must never run in the browser should carry `import "server-only"`. Without it, Next.js can silently include these modules in a client bundle and surface a cryptic "Cannot find module" error at runtime instead of a clear build-time failure.

- **Community Decks page: source widgets + filter panel, scraping deferred**
  The `/decks` route shows four deck-source widgets (Piltover Archive, Riftdecks, The Vault, MetaWatch) with a filter panel (legend, deck type, ranking, date range). Actual scraping is not implemented — a "coming soon" placeholder renders when a source is selected. The `decks/page.js` server component fetches legends from DynamoDB and passes them as props to the client component so the legend filter is populated from real data when the DB is available.

## Topics Discussed

- **Stale `package-lock.json` in home directory** — npm was detecting `/Users/chautuananh/package-lock.json` (no accompanying `package.json`) as the project root. Fixed by deleting the orphaned file.
- **"Cannot find module @aws-sdk/client-dynamodb"** — packages were installed but the error surfaced because `db.js` lacked a `server-only` guard, allowing Next.js to include it in a client bundle. Adding the guard converts the runtime error into a clear build-time failure.
- **`unstable_cache` 2 MB limit** — discussed alternatives: ISR (chosen), Redis/DAX (deferred infrastructure), chunked caching by set (unnecessary complexity). ISR is sufficient because the card set is stable and only one route consumes `getAllCards`.
- **Package audit** — reviewed `npm outdated`. Minor/patch bumps for Next.js, React, `@types/react` are safe to apply. `eslint` 10, `typescript` 6, and `@types/node` 25 are major bumps held back until there is time to validate breaking changes.
- **Variant card grouping** — discussed ID normalisation via regex vs. name matching. Name matching is simpler, has no edge cases with ID format changes, and aligns with how the validator was going to work anyway.

## Bug Fixes

- **Orphaned `package-lock.json` in home directory**
  npm's root detection picked up `/Users/chautuananh/package-lock.json` instead of the project lockfile. Fixed by deleting the stale file from the home directory.

- **"Cannot find module @aws-sdk/client-dynamodb"**
  `db.js` was missing `import "server-only"`, which meant Next.js could include the AWS SDK in a client bundle where Node.js modules are unavailable. Fixed by adding the guard to both `db.js` and `cards.js`.

- **`unstable_cache` throwing 2 MB exceeded error**
  `getAllCards` wrapped in `unstable_cache` exceeded the data cache size limit. Removed the wrapper and switched to ISR via `export const revalidate = 3600` on `page.js`.

- **`CARDS` undefined reference in `user/page.js`**
  Line 168 called `CARDS.find(...)` on a variable that was never defined. The page is all mock data and does not yet load real cards. Removed the broken lookup and replaced the expanded deck card chips with a placeholder.
