# Sunday 25 October 2026 - Dev Log No. 15

EloShowdown stopped updating when Riftbound's events moved from UVS to Riot's
PlayRiftbound site, so match history, Elo and player search now come from
BoundRift. Tournament lookup moved off UVS onto BoundRift events too, found by
learning the stores each player plays at. Rows saved from EloShowdown are
re-keyed onto BoundRift's, opponent renames are handled, and stray rows can be
paired by hand. The Data tab now reports across every linked account, and the
summary card shows the most played legend.

---

## Decisions Made

- **Use BoundRift for match history, Elo and player search.**
  - It's the only source still updating.
  - It rates matches from both UVS (before October 2026) and PlayRiftbound (after).
  - It merges a player's Riot account into their old UVS record, so one player id covers both eras.
  - It has no documented API. We use the JSON endpoints its own site loads, called server-side and cached. Its terms only forbid traffic heavy enough to slow the site down.
- **Use BoundRift for events too, instead of calling PlayRiftbound directly.**
  - Riot's event site is a GraphQL API that only accepts pre-registered query hashes. Those change whenever Riot redeploys, so calling it directly would keep breaking.
  - BoundRift already ingests PlayRiftbound events. It also maps PlayRiftbound tournament ids to its own event ids.
- **Find events by learning each player's stores** (the user's choice over "paste links only" or "month only").
  - BoundRift's player data gives a match's month but never its day or event.
  - Checking every event near a player took 245 requests and 3 minutes per month in Sydney.
  - Stores are learned from events rows already link to, event names on saved rows and drafts, and pasted links. Checking only those stores' events costs about 5–10 requests a month.
- **Re-key saved EloShowdown rows onto BoundRift rows** (the user's choice over keeping both).
  - EloShowdown's match ids and Elo differ from BoundRift's.
  - Rows are paired by season, result, opponent and month. Picks follow the pair, and BoundRift's Elo replaces EloShowdown's so the chart uses one rating system.
  - The old item is marked `rekeyedTo`, never deleted, so the change is reversible and no data is lost.
- **Prefix BoundRift ids with `br-`** for accounts, matches and opponents.
  - EloShowdown and BoundRift ids share the same numeric range.
  - Without the prefix, linking a friend could overwrite an account, or picks could attach to the wrong match.
  - Accounts linked through EloShowdown keep their id, so their saved matches stay keyed by it, and gain a `boundrift_id`.
- **Seasons are BoundRift's set names, kept in a static table.**
  - BoundRift has no API for sets.
  - The table mirrors BoundRift's own list (Origins … The Reckoning).
  - EloShowdown season slugs are mapped onto the set names.
- **Picks on re-keyed rows are derived at render time (`withLegacyPicks`) instead of copied across.**
  - Pairs can now form *after* events arrive, inside a state update, where copying picks would be unsafe.
- **Pair a renamed opponent by event, not by name.**
  - BoundRift shows players' current names (e.g. SDPhantom → Kin).
  - Once an event is known, a leftover saved row pairs with that event's one leftover BoundRift row of the same result.
  - It only pairs when there's exactly one candidate on each side, so picks can't land on the wrong round.
- **Event linking moved onto each "Event not found" header.**
  - The global paste box gave no hint which matches a link was for.
  - A per-group form can check that the pasted event actually contains those matches.
- **Manual "Same match as…" instead of a remove option.**
  - Saved rows that never pair are usually real matches BoundRift never recorded, so removing them would delete real games and their picks.
  - Pairing by hand keeps the picks and needs no delete in the Lambda.
- **Don't delete the EloShowdown data.**
  - Saving already supersedes every row that pairs.
  - The rest are real games, and before May 2026 the only source of exact dates.
- **Data tab defaults to all linked accounts, with an account filter.**
  - Elo is per account, so the Elo panel asks for a single account when several are shown.
- **Search results show BoundRift's game score in the score box**, but only on rows where no score was ever picked. These auto-filled scores don't count as unsaved picks.

## Bug Fixes

- **Matches stopped updating.**
  - Cause: EloShowdown froze once Riftbound's events moved to PlayRiftbound in October 2026.
  - Fix: moved to BoundRift (above).
- **Events with the same name were split into two groups.**
  - Cause: the opponent had renamed, so the saved row and its BoundRift row didn't pair and kept different event keys.
  - Fix: pairing by event, and leftover saved rows join a linked event's group.
- **A renamed opponent still showed twice after saving.**
  - Cause: the deployed save Lambda drops `eventId`, so pairing by event (which needed an event id) didn't run.
  - Fix: events match on name + date when either row lacks an id.
- **September events were never looked up in a busy city centre.**
  - Cause: one 48-event cap across all months; October's 72 nearby events used it up.
  - Fix: a budget per month, the stores' own events first, and an early stop once a month's matches are found.
- **Event lookup found too few events.**
  - Cause: BoundRift's nearby search returns only skirmishes unless every category is requested.
  - Fix: request every category.
- **The header Elo was blank.**
  - Cause: the newest rows were unrated sealed matches.
  - Fix: use the newest rated row.
- **Common event names never resolved.**
  - Cause: BoundRift's name search returns only its 10 newest results.
  - Fix: fall back to the event near the main store at the exact start time.
- **The right candidate was missing from "Same match as…".**
  - Cause: month-only rows had no date to sort by, and an 8-item cap cut the list.
  - Fix: show every candidate, newest first, in a scrolling list.
