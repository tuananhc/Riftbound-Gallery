# Tuesday 20 October 2026 - Dev Log No. 14

Built a phone version of the whole site from the Claude Design mobile mockup. It
keeps top navigation, uses bottom sheets for pickers and works with server-safe
CSS-variable breakpoints. Added a season filter to the profile tabs, backed by
EloShowdown's seasons list, and replaced every native `<select>` with a custom
`Dropdown`. Fixed the Data tab's "All seasons" view, which hid legends and drew
one Elo line across seasons. Also aligned the History rows' score column, and
traced why scores aren't reaching DynamoDB: the Lambda changes haven't been
deployed.

---

## Decisions Made

- **Phones keep top navigation instead of the design's bottom tab bar.**
  Riftbound is a website, not an installed app. A logo bar plus a row of four
  page links matches how people use websites and keeps one navigation model
  across sizes. The Claude Design mockup's bottom tab bar was offered and
  declined; everything else in the mockup was followed.

- **Responsive switching uses two mechanisms, chosen by where the markup
  renders.**
  - Server-rendered markup (navbar, card grid, deck filters, news, dev log,
    sign-in) switches with CSS variables set by one `@media (max-width: 640px)`
    rule in `BASE_STYLES`: `SHOW.*`, `LAYOUT.*` and `STRIP`. This is the same
    trick as the theme. The first paint is already correct, so nothing flashes
    or causes a hydration mismatch.
  - Client-only UI (the profile, sheets versus popovers) uses `useIsMobile()`.
    It is a `useSyncExternalStore` over `matchMedia`, which is fine because
    that UI only renders after the client has loaded.
  - A `<style>` media block per component or a JS-only breakpoint were both
    rejected. The first breaks the inline-styles rule; the second flashes the
    desktop layout on phones.

- **Pickers, filters and detail views are bottom sheets on phones.**
  Sheets put the controls in the thumb zone and give room for 44–52px touch
  targets. Desktop keeps popovers. `BottomSheet` is one shared component (drag
  the handle to dismiss, Esc, scrim, body scroll lock) so every sheet behaves
  the same way.

- **No native `<select>` anywhere; use `Dropdown`.**
  The OS draws the option list of a native select, so it ignores the theme,
  the square corners and the font. `Dropdown` has three variants (`field`,
  `compact`, `text`). It shows a square popover on desktop that flips upward
  when there's no room below, and a bottom sheet on phones. It is fully
  keyboard-operable. Recorded as a rule in `CLAUDE.md`.

- **The season is chosen once, beside the DATA / HISTORY tabs, and drives both
  tabs.**
  - Options come from `GET /api/elo/seasons` (EloShowdown), plus
    "All seasons".
  - It defaults to the current season (`is_current`), else the newest saved
    season.
  - The slug feeds `elo-history?season=<slug>` when you press Search.
  - Rows saved before seasons were stored are placed by date
    (`seasonOfMatch`), so old data still filters correctly.
  - If the seasons call fails, the selector falls back to the seasons found
    in saved rows.

- **Guests auto-load a season when they switch; signed-in users press
  Search.** A guest has nothing saved, so an empty view would be useless.
  Signed-in users see their saved rows immediately and choose when to hit
  EloShowdown, which keeps the earlier "Search is manual" decision.

- **The Data tab shows every legend; no top-N cap.**
  The 8-legend cap hid real data once matches across seasons were combined.
  The matchup grid already scrolls sideways, and the phone version never had
  a cap.

- **The Elo chart breaks at each season change.**
  Elo resets every season, so a continuous line drew a misleading drop from
  one season's end rating to the next season's starting rating. Each season is
  now its own line and area, separated by a dashed divider and a short label
  (`S3`, `S4`). On the phone chart the labels are HTML rather than SVG text,
  because that SVG is stretched with `preserveAspectRatio="none"`.

- **History rows use fixed columns for result / score / Elo change.**
  Centring the three items as one group made the score box drift with the text
  width ("LOSS" vs "WIN", "-6" vs "-14"). A `48px 60px 48px` grid keeps every
  score box on the row's centre line.

## Bug Fixes

- **"All seasons" in the Data tab didn't show every legend.**
  - Cause: the desktop "Vs opponent legend" list and the Matchups grid were
    capped at the 8 most-faced opponent legends (`MAX_MATCHUP_COLS`).
  - Fix: removed the cap and its note.

- **The Elo chart drew one continuous line across seasons.**
  - Cause: `eloSeries()` is chronological across all matches, and Elo resets
    each season.
  - Fix: `seasonRuns()` splits the series wherever `seasonOfMatch` changes.
    Each run gets its own line, separated by a dashed divider and an `S<n>`
    label.

- **Score boxes didn't line up between History rows.**
  - Cause: result, score and Elo change were centred together in a flex row
    whose width depended on the text.
  - Fix: a fixed three-column grid, with an empty Elo slot kept for 0-change
    draws.

- **The phone page scrolled sideways (462px wide at 390px).**
  - Cause: rotated battlefield cards overflowed the card grid.
  - Fix: `overflowX: "clip"` on the `CardGrid` section.

- **The local dev server hung on a flaky network.**
  - Cause: `getaddrinfo ENOTFOUND` for DynamoDB during server rendering.
  - Fix: restarted the dev server; UI checks used temporary pages with
    synthetic data, deleted afterwards.

- **Scores aren't saved to DynamoDB.**
  - Cause: identified this session, not yet fixed in production. The Lambda
    changes that add `score` are uncommitted, so the deployed Lambdas drop
    and omit the field.
  - Fix: commit and push to `master` to trigger `deploy-backend.yml`.
