# Thursday 15 October 2026 - Dev Log No. 13

Got the Vercel deployment serving the app, then reworked the look of the site:
a single blue accent and a light/dark theme built on CSS-variable tokens. Most
of the session went into match history. It now loads from DynamoDB through a
new `GET /history` Lambda, stores every EloShowdown field, and has a reworked
legend picker. The profile gained a Data tab with Elo, legend and matchup
analysis. The README now documents the whole cloud architecture.

---

## Decisions Made

- **Stay on Vercel rather than moving to Amplify Hosting.**
  The 404 was a project setting, not a platform problem. Vercel supports
  Next.js 16 from day one. Amplify's Next.js 16 support isn't clearly
  documented by AWS, and it reportedly lacks on-demand ISR. Amplify's real
  advantages (IAM role instead of access keys, one AWS bill) can be had on
  Vercel with OIDC federation if needed. Revisit if the site goes commercial,
  since the Hobby plan is non-commercial only.

- **The README links the stable production domain, not a per-deployment URL.**
  `riftbound-gallery-<hash>-….vercel.app` URLs sit behind Vercel's deployment
  protection (visitors get a login redirect) and change on every deploy.
  `riftbound-gallery.vercel.app` always points at the latest production build.

- **Theme colours are CSS variables generated from one palette per theme.**
  `THEMES.dark` / `THEMES.light` in `src/lib/data.js` hold the hex values;
  `COLORS.x` is `var(--x)` and `BASE_STYLES` points the variables at the active
  palette via `<html data-theme="light">`. Switching themes is then one
  attribute change with no React re-render. Server components keep working
  because the tokens are just strings. Every hardcoded colour in components was
  converted so that every surface follows the theme.

- **Translucent colours go through `alpha(color, percent)`.**
  Appending a hex alpha suffix (`COLORS.accent + "55"`) produces invalid CSS
  once the token is a `var()`. `color-mix(in srgb, …)` works with variables
  and literals alike.

- **The saved theme is applied before first paint by an inline script in
  `layout.js`.** The script reads localStorage and sets the attribute before
  React hydrates, so there is no flash of the wrong theme. `useTheme` uses
  `useSyncExternalStore` with a "dark" server snapshot, so hydration never
  mismatches. Dark stays the default.

- **One blue for the whole UI.**
  The accent first moved from grey-blue `#8fa3bf` to sky blue `#8ecbff`
  (option D of six samples). Once DRAW was made blue as well, two shades of
  blue sat side by side, so the accent was set to the draw blue: `#6aa8ff` in
  dark mode and `#2563c9` in light mode, deeper for contrast on white. The
  `accent` and `draw` tokens stay separate names with equal values, so they can
  diverge later without touching components. The Gold rank badge had reused
  the old draw yellow through the codemod and was given its own fixed colour.

- **Legend names are title-cased for display only.**
  Cards are stored in caps ("EMPEROR OF THE SANDS"). `legendLabel()` renders
  "Azir - Emperor of the Sands", keeping minor words lowercase and
  capitalising both halves of hyphenated words. Filters and saved decks still
  match on the raw `name`.

- **Match rows show legend icons, not art.**
  Each row is now a three-column grid: `[icon] You - Legend - runes`, then the
  result and Elo change, then `Opponent - Legend - runes [icon]`. The old
  half-row overlays with champion art covered the centre text whenever a
  picker opened, and the art made the rows hard to scan.

- **The legend picker is portalled to `<body>` with fixed positioning.**
  Positioned inside the match list, it was trapped below the profile card's
  stacking context. Rendering it at the top level fixes that for good. It
  measures the row on open, flips upward when there isn't room below, and
  closes on page scroll or resize rather than drifting away from its row.

- **Rune icons: PNG on the match rows, none in the selectors.**
  After a few iterations the domain runes (`resources/Rune_<Domain>.png`) show
  only next to picked legends on the rows; the pickers list champion and
  legend name only. The SVG runes in `COLOR_CONFIG` are still used by the card
  filters, deck panel and card modal.

- **Saved history is the source of truth; EloShowdown is fetched only on
  demand.** On load, the page reads the active account's matches from
  `MatchHistory`. The **Search** button pulls the latest EloShowdown history
  and merges it in: EloShowdown wins for matches in both, while matches only in
  the saved history (e.g. earlier seasons) are kept, and picks are untouched.
  This removes an external call from every page load and means the page always
  shows what's actually stored.

- **An explicit empty pick clears the stored one; an absent field is left
  alone.** `save-match-history` `REMOVE`s `myChampion` / `opponentChampion`
  when they're sent as `null` or `""`, but still never touches fields missing
  from the payload (so notes written elsewhere survive). A **Clear pick**
  option makes a wrong pick undoable. Saving is disabled until the saved
  history has loaded, because a save with empty picks after a failed load would
  wipe every stored pick.

- **`GET /history` is its own Lambda with bounded, paginated reads.**
  It Queries `userId = sub AND begins_with(accountMatchId, "<eloPlayerId>#")`
  with `Limit` 200 and returns an opaque cursor. That follows the CLAUDE.md rule
  of bounding reads with `Limit` + `LastEvaluatedKey` rather than deleting
  items. The cursor is checked to belong to the caller's partition and the
  requested account, so it can't be used to page into someone else's data. The
  role is read-only (`dynamodb:Query`).

- **Every field of an EloShowdown `elo-history` point is stored.**
  `eloBefore`, `eloChange`, `eloAfter`, `opponentId` and `season` were added
  alongside the existing fields, so the rows, stats and charts can render from
  the database alone. A real match was round-tripped through both Lambdas with
  no field lost.

- **Your legend pick fills the whole event by default.**
  Players almost always run one legend per event, so the picker has an "Apply
  to all N matches in this event" checkbox, on by default. An event is the
  resolved tournament, or the day while it's still being looked up. Opponent
  pickers stay per-match.

- **Elo change is hidden when it's 0.**
  A draw between equal ratings moves nothing, so the result alone says it. A
  draw that does move Elo still shows the change.

- **Profile analysis: Data and History tabs, with Data first.**
  Of three mockups, A (dashboard) became the Data tab's default **Overview**.
  It shows Elo over time beside the per-legend record, with opponent legends
  full width below. B (the matchup grid, plus best / toughest matchup and
  most-played opponent) is the **Matchups** view behind a toggle, as asked
  ("not the first thing the user sees"). Season and Legend filters apply to
  both. All stats are pure functions in `src/lib/matchStats.js`.

- **Headline stats live in an expandable user card, scoped to the latest
  season.** A one-line `ELO · W-L-D · win%` summary expands to five tiles
  (Elo, Peak, Record, Win%, Streak). Elo restarts each EloShowdown season, so
  the card covers the latest one. Like the Data tab, it counts saved matches
  only, so the numbers match what's stored.

- **The Elo chart is drawn at its real pixel width.**
  A `viewBox` stretched to the panel scaled the axis text and line width with
  the screen. A `ResizeObserver` now sizes the SVG in pixels, at a fixed 180px
  height.

- **The architecture overview lives in the root README.**
  The README is what GitHub shows first, so the "what talks to what" overview
  goes there, with Mermaid diagrams that GitHub renders natively.
  `infra/README.md` stays the backend runbook and is linked from it. CLAUDE.md
  shouldn't duplicate it, or the two will drift.

- **Commits go straight to `master`.** Asked explicitly, since a push to
  `master` deploys both the site and the backend.

## Bug Fixes

- **Production URL returned `404 NOT_FOUND` despite a successful deploy.**
  - Cause: the Vercel project wasn't set to the Next.js framework preset and
    had its output directory set to `.next`, so the build folder was published
    as static files. Server bundles under `/server/...` were publicly readable
    as a result.
  - Fix: set Framework Preset to Next.js, clear the output directory override,
    and redeploy (a dashboard change, not code). Confirmed afterwards that `/`
    returns 200 from Next.js.

- **Re-saving match history didn't fix earlier picks.**
  - Cause: the page never loaded saved picks, so after a reload rows looked
    empty while DynamoDB still held them. On top of that, the Lambda's
    `clean()` dropped `null`s, so an empty pick could never overwrite a stored
    one.
  - Fix: saved history (with picks) loads from `GET /history`; explicit nulls
    are `REMOVE`d; "Clear pick" was added; saving is gated on a successful
    load.

- **The legend picker hid the row's centre text, and the profile card covered
  its search box.**
  - Cause: each picker half was an absolutely positioned 50% overlay raised to
    z-index 60 when open. Its dropdown was trapped inside the match list's
    stacking context, below the profile card.
  - Fix: a non-overlapping three-column grid, plus a picker portalled to
    `<body>` with fixed positioning.

- **Legend names showed in all caps.**
  - Cause: card names are stored uppercase.
  - Fix: display-only `titleCase()` via `legendLabel()`.

- **Oversized Elo chart and axis numbers on wide screens.**
  - Cause: an SVG `viewBox` scaled to 100% width scaled its text too.
  - Fix: size the SVG in real pixels with a `ResizeObserver`.

- **"Showing the 8opponent legends" was missing a space.**
  - Cause: the JSX compiler dropped the space between `{MAX_MATCHUP_COLS}` and
    the following text on that line.
  - Fix: render it as one template string.

- **The Gold rank badge would have turned blue with DRAW.**
  - Cause: the colour codemod mapped its `#bdb76b` to the `draw` token because
    the hex happened to match.
  - Fix: give rank badges their own fixed colours again.
