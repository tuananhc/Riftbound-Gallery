# Sunday 25 May 2026 - Dev Log No. 5

Extended the Community Decks page with multi-source selection and a full filter panel. Source widgets now support multi-select so the crawler can pull from any combination simultaneously. A filter bar above the widgets exposes four criteria — legend, date range, deck type, and ranking — with the legend control starting as multi-select pills before being redesigned as a custom image-aware dropdown.

---

## Decisions Made

- **Multi-select source widgets instead of single-select**
  Changed `selectedId` (string) to `selectedIds` (Set) so users can toggle any number of sources independently. The results panel already accepted an array of sources, so the downstream change was minimal. This matches the stated intent: the crawler should pull from all selected sources and merge results into one list.

- **Filter state as a flat object in `DeckSources`, passed down to `DeckFilters`**
  All four filter values live in a single `filters` state object in the parent (`DeckSources`). `DeckFilters` is a pure presentational component that receives `filters`, `onChange(key, value)`, and `onClear`. This keeps the filter state in one place so the crawler integration can read a single object when it's wired up, rather than reaching into multiple hooks.

- **Custom dropdown for the legend filter instead of a native `<select>`**
  Native `<select>` options cannot render images. A custom dropdown was built to show each legend's card image (28×28) alongside the formatted label. This required switching from multi-select (Set) to single-select (string) for the legend field, which is appropriate for a deck-filter context where you're searching for decks built around one specific legend.

- **`filters.legend` as a plain string, not a Set**
  Multi-select legend pills were replaced with a single-value dropdown. The filter field was renamed from `legends` (Set) to `legend` (string, `""` = no filter). `activeCount` was updated to check `!== ""`. This simplifies the clear logic and the eventual query sent to the crawler.

- **`page.js` passes `image` and `tags_text` per legend**
  The server component already filtered cards to Legend type and passed `{ id, name }`. Extended to include `image` and `tags_text` so the client dropdown can render the card thumbnail and the `${tags_text} - ${name}` label without any additional fetch.

## Topics Discussed

- Whether legend filter should be single-select or multi-select: single-select was chosen because deck lists are built around one legend and filtering by multiple legends simultaneously would return an unfocused list.
- Native `<select>` limitations with images — browser-rendered `<option>` elements cannot display images, so a fully custom dropdown was the only path.
- Click-outside close pattern using `useRef` + `useEffect` document `mousedown` listener, cleaned up on effect teardown to avoid memory leaks.
- `colorScheme: "dark"` on date inputs to get the browser's native dark calendar picker without needing a third-party date library.
