## Decisions Made

- **Tabs over spaces, enforced via `.vscode/settings.json`**
  Five files were using 2-space indentation while the rest of the project used tabs. Converted all files to tabs and added `.vscode/settings.json` with `insertSpaces: false`, `tabSize: 4`, and `detectIndentation: false` so VS Code no longer overrides the setting per file.

- **Next.js Route Handler with streaming instead of Lambda for on-demand crawling**
  Lambda + API Gateway has a hard 29-second synchronous response timeout and does not support response streaming through API Gateway. Since the user wants results displayed immediately without storing in a database, a Next.js Route Handler with `ReadableStream` is the right fit — it streams results per source as each crawl completes, and Vercel Pro allows up to 60 seconds. Lambda remains appropriate only for scheduled background crawls with DynamoDB storage, which is not the chosen pattern here.

- **NDJSON streaming with `Promise.allSettled`**
  Each crawler runs in parallel. As soon as one finishes, its results are written to the stream as a newline-delimited JSON chunk. `Promise.allSettled` ensures one crawler failure doesn't abort the others — failed sources send back `{ sourceId, error }` so the UI can show per-source error states.

- **Crawlers live in `src/lib/crawlers/`, one file per source**
  Crawlers are pure async functions with no React or UI — they belong in `lib/`. One file per source (`piltover-archive.js`, `riftdecks.js`, `the-vault.js`, `metawatch.js`) keeps them independently testable and easy to add or remove. Each will carry `import "server-only"` to prevent accidental client inclusion.

- **`DeckSources.js` split into six focused files**
  The original 636-line file mixed data, a complex dropdown, a filter panel, a source card, and a results panel into one file. Split into single-responsibility files so each component can be read, tested, and modified without touching the others.

## Topics Discussed

- **Lambda vs Route Handler for live crawling** — Lambda + API Gateway ruled out due to the hard 29-second synchronous response cap and lack of native streaming support through API Gateway. Route Handler with `ReadableStream` is simpler and fits Vercel's execution model.
- **Scheduled vs on-demand crawling** — if results were stored in DynamoDB, Lambda on an EventBridge schedule would be ideal (no cold start penalty visible to users, decoupled from page load). Since the user wants live display without storage, the on-demand streaming pattern is used instead.
- **Where to put Route Handlers** — `src/app/api/<name>/route.js` per Next.js App Router convention.
- **Where to put crawlers** — `src/lib/crawlers/` as pure server-only async functions, consistent with the existing `lib/` convention.
- **Component decomposition** — walked through the 636-line `DeckSources.js` and identified five natural split points.
